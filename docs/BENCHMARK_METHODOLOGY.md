# Benchmark methodology

Architecture Baseline v0 is a controlled, provider-backed experiment designed to answer a narrow systems question:

> Can paired model evidence support a selective multi-model policy that preserves useful quality while reducing the cost and latency of always consulting two models?

It is not a general model leaderboard and it is not evidence about an unseen domain. It measures a frozen generic corpus, exact providers, exact prompts, and exact runtime conditions.

## Experimental basis

The deterministic corpus contains 72 objective cases across twelve task families, with six cases per family:

| Task family | What is tested |
|---|---|
| Structured extraction | Exact JSON fields and values. |
| Classification | Binary allow/deny decisions. |
| Numerical reasoning | Arithmetic over supplied token and call counts. |
| Mathematical reasoning | Small linear equations. |
| Logical reasoning | Consequences of stated predicates and missing evidence. |
| Planning | A unique order satisfying precedence constraints. |
| Evidence verification | Supported versus insufficient-evidence judgments. |
| Critique | Identification of a named reasoning or experimental flaw. |
| Synthesis | Reconciliation under a mandatory policy. |
| Tool-use reasoning | Selection of the single suitable tool. |
| Code understanding/debugging | Identification of a Python exception class. |
| Uncertainty/abstention | Correct answer or explicit `INSUFFICIENT_EVIDENCE`. |

The corpus is generated by `backend/app/benchmark/corpus.py`. Cases are inputs with deterministic expected answers; they do not contain generated model outputs.

## Split discipline

| Split | Cases | Permitted use |
|---|---:|---|
| Development | 48 | Implementation checks and exploratory analysis. |
| Tuning | 12 | Gate, task-owner, and policy selection. |
| Held-out | 12 | One evaluation after all choices are frozen. |

The gate used 60 development+tuning cases per model and zero held-out observations. Only after the gate configuration was serialized and hashed were the 12 held-out cases executed.

## Models and providers

The full 72-case paired baseline used:

- `openai/gpt-oss-20b` through Groq;
- `qwen/qwen3.8-27b` through Groq;
- `deepseek/deepseek-v4.1-flash` through OpenRouter.

Provider diagnosis separately tested the configured Claude candidate and a Haiku control through Anthropic, plus the configured Gemini model. Diagnosis is reported as availability evidence and is not included in the three-model quality table.

## Frozen inference protocol

- Identical case order for every core model.
- Temperature `0`.
- Maximum output `256` tokens.
- Conservative budget cap of `1,024` input and `256` output tokens per core call.
- One repetition and fixed seed `0`.
- Concurrency `1`.
- No silent prompt change between models.
- No retries that would obscure provider availability.
- Every observation written immediately to JSONL.

The system prompt requests only the requested answer with no explanation or Markdown. The prompt hash and model configuration are stored on observations.

## Scoring

`SCORING_V1` is frozen and deterministic. It uses exact objective comparison with only predeclared canonicalization:

- surrounding whitespace is trimmed;
- text comparison is case-insensitive;
- terminal punctuation is normalized;
- comma spacing is normalized for planning sequences;
- a small declared set of equivalent critique labels is accepted;
- structured extraction uses exact JSON comparison.

The earlier exact-match result is retained as a secondary reproducibility field. No alias was added after provider execution began.

## Call accounting

| Phase | Provider calls | Purpose |
|---|---:|---|
| Provider diagnosis | 3 | Classify configured provider/model access safely. |
| Three-model baseline | 216 | 72 identical cases × 3 models. |
| S0–S4 replay | 0 | Reuse paired observations without fabricating new outputs. |
| Provider-backed selective verification | 14 | Seven actual escalations for `S3` and seven for `S4`. |
| Total | 233 | Below the authorized 245-call ceiling. |

The conservative reserved spend was `$0.17888128`; token-based estimated spend from successful recorded calls was `$0.00941611`. These are estimates based on the checked pricing table, not a provider invoice.

## Compared policies

| ID | Definition |
|---|---|
| `S0` | GPT-OSS only. |
| `S1` | Qwen only. |
| `S2` | Always execute Qwen and GPT-OSS, then apply frozen reconciliation. |
| `S3` | Qwen first; call GPT-OSS only when the frozen gate escalates. |
| `S4` | GPT-OSS first; call Qwen only when the frozen gate escalates. |

Allowed gate signals are limited to task family, schema or constraint failure, task risk level, historical task-family error upper bound, and explicit abstention. Ground truth is never available to the router.

## Offline replay versus provider-backed execution

These evidence types must not be conflated:

- **Offline replay estimate:** combines already-recorded paired single-model answers under a frozen routing and reconciliation rule. It makes zero new provider calls.
- **Provider-backed confirmation:** reuses the recorded first answer but actually invokes the verifier for each case selected by the frozen gate.

The report labels both explicitly. An offline replay is not described as an executed multi-agent system.

## Metrics and uncertainty

The baseline records:

- provider success and failure;
- correctness conditional on successful provider response;
- end-to-end operational correctness;
- malformed output, abstention, severe failure, and constraint violation;
- input/output tokens, estimated cost, and latency;
- task-family breakdown;
- paired loss covariance and correlation;
- disagreement, failure overlap, Jaccard similarity, and conditional rescue;
- empirical and robust Pareto status;
- escalation, rescue, damage, incremental cost, and incremental latency;
- worst-case and lower-tail behavior;
- weak prior sufficient statistics.

Wilson intervals are used for proportions. Mean quantities and paired differences use deterministic percentile bootstrap intervals with 2,000 resamples. Paired binary comparisons use exact McNemar tests where applicable. Covariance uses paired cases and a `0.25` diagonal-shrinkage sensitivity view.

## Reproducing analysis without provider calls

The existing observations can be inspected and rendered without contacting a provider:

```powershell
Push-Location .\backend
python -m app.benchmark.baseline_execute --root .. --render-existing-summary
Pop-Location
```

The offline test suite is:

```powershell
Push-Location .\backend
$env:PYTHONPATH='.'
$testRoot = Join-Path (Resolve-Path ..) '.pytest-eigenbrains'
python -m pytest tests -q --basetemp $testRoot
Pop-Location
```

Do not execute the live baseline module again: the frozen output directory exists, and the runner intentionally refuses to overwrite it or duplicate calls.

## Limitations

- The corpus is objective and generic, not domain-specific.
- There is only one observation per model/case configuration.
- Held-out `n=12` produces wide quality and tail-risk intervals.
- Provider availability is a property of the measured window, not a permanent provider rating.
- The selected GPT-OSS/Qwen pair was intentionally studied; the full covariance results indicate DeepSeek was more complementary, but no additional architecture experiment was authorized.
- Equal observed quality is not proof of equivalence.
